## Title
Fake News Detection and Classification: A Comparative Study of Convolutional Neural Networks, Large Language Models, and Natural Language Processing Models

## Year
2025 (Received 14 November 2024; Revised 17 December 2024; Accepted 8 January 2025; Published 9 January 2025)

## Venue
Future Internet 2025, 17, 28 (MDPI)

## DOI
https://doi.org/10.3390/fi17010028

## Research Objective
To investigate the effectiveness of advanced machine learning models—convolutional neural networks (CNNs), BERT, and generative pre-trained transformers (GPTs)—for robust fake news classification, comparing performance before and after fine-tuning (with few-shot learning), and examining the cost/trade-offs of fine-tuning LLMs for the news sector.

## Research Questions
- Q1: Are traditional NLP and CNN models or LLMs more accurate in fake news detection tasks?
- Q2: Among the GPT-4 Omni family, which model performs best prior to fine-tuning?
- Q3: After fine-tuning with few-shot learning, which model in the GPT-4 Omni family demonstrates superior performance?
- Q4: What is the significance of the costs associated with fine-tuning LLMs, and how do these costs impact performance in the news sector?
- Q5: How can LLMs be effectively leveraged to assess fake news, and what transformative effects can they have on the news industry through automated detection and actionable insights?

## Dataset(s)
WELFake dataset (sourced from Kaggle). Compiled by merging four sources: Kaggle, McIntire, Reuters, and BuzzFeed Political. Available under Attribution-NonCommercial 4.0 International license.

## Dataset Size
- WELFake: 72,134 news articles total (35,028 labeled real (0) and 37,106 labeled fake (1)); total size 245.09 MB; usability rating 10.
- After text-length restriction (max 2560 characters): 7,573 real (1) and 7,313 fake (0); after data standardization and empty-row re-check: 7,568 real (1) and 7,313 fake (0).
- After balanced stratified sampling: 5,000 entries (2,500 per class).
- Split: Training 80% (3,200 samples), Testing 20% (1,000 samples), Validation 20% of training (800 samples).
- Fine-tuning token count: 2,172,192 tokens (each for gpt-4o and gpt-4o-mini).

## Language(s)
Not Reported explicitly (WELFake is an English-language news dataset per the source; the paper does not explicitly state the language).

## Task
Binary fake news detection/classification (0 = fake, 1 = not fake/real).

## Model(s)
- GPT-4 Omni family LLMs: gpt-4o (gpt-4o-2024-08-06) and gpt-4o-mini (gpt-4o-mini-2024-07-18), both base (zero-shot) and fine-tuned.
- BERT: bert-base-uncased (BertForSequenceClassification).
- CNN: custom 1D-convolutional model (Keras/TensorFlow).

## Architecture Type
- GPT-4o / GPT-4o-mini: autoregressive decoder-only transformer LLMs (fine-tuned via OpenAI API; Azure reportedly uses LoRA/PEFT/DeepSpeed).
- BERT (bert-base-uncased): encoder-only transformer, 12 transformer layers, 768 hidden units, 12 attention heads, ~110 million parameters, with a sequence-classification head (fully connected layer).
- CNN: embedding layer → 1D convolutional layer → global max pooling → dense (ReLU) → dense (sigmoid) output.

## Preprocessing Pipeline
1. Column Removal: removed "Unnamed: 0" column.
2. Empty Row Removal: removed rows with missing values in Title/Text/Label.
3. Column Merging: merged "Title" and "Text" into a consolidated "Text" column.
4. Label Standardization: standardized/renamed label column to "Label".
5. Text Length Restriction: max 2560 characters (≈512 tokens) for the "Text" column.
6. Data Standardization: standardized dataset and re-removed empty rows.
7. Balanced Sampling: stratified sampling to select 5,000 entries (2,500 per class).
8. ID Addition: assigned unique ID to each entry.
Longer articles were removed to standardize input sizes across models for fair comparison. For BERT: tokenization via BERT tokenizer. For CNN: Keras Tokenizer + pad_sequences.

## Training Strategy
- Each model generated predictions on the test set both before and after fine-tuning.
- GPT models: base models used in zero-shot with a model-agnostic JSON-output prompt; then fine-tuned via OpenAI API on JSONL prompt–completion pairs (multi-epoch), two fine-tuning jobs (ftjob-9qj8DZgmx07iwoJsn8JOhx7c and ftjob-v10NfwXqreR6rmZNFuNOeqLV).
- BERT: fine-tuned on Google Colab (Tesla V100-SXM2-16GB GPU) over three epochs with Adam optimizer; backpropagation each epoch.
- CNN: TensorFlow/Keras, compiled with Adam optimizer and binary cross-entropy loss, trained over three epochs.
- Consistent hyperparameters maintained across all models for fair training.

## Hyperparameters
Consistent across all models: learning rate 2 × 10^-5, batch size 6, three (3) training epochs, Adam optimizer.
- For GPT models via OpenAI API, only batch size, learning rate, and number of epochs were controllable.
- BERT: bert-base-uncased; ~110M parameters; 512-token input limit (≈2560 characters); Adam optimizer; 3 epochs.
- CNN: Adam optimizer; binary cross-entropy loss; sigmoid output; 3 epochs; embedding layer + 1D conv + global max pooling + dense layers.
- GPT-4o can process inputs up to 128,000 tokens (context window).

## Evaluation Metrics
Accuracy, Precision, Recall, F1-score. Also fine-tuning metrics: training loss, validation loss, training time (seconds), training cost (USD).

## Baseline Models
Base (zero-shot, pre-fine-tuning) GPT-4o and GPT-4o-mini serve as baselines; the CNN and BERT models serve as comparison points against the fine-tuned LLMs. (No external prior-work model rerun as baseline; comparisons are internal across the four models before/after fine-tuning.)

## Main Results
Model performance (Table 3; Accuracy / Precision / Recall / F1):
- base gpt-4o-2024-08-06: 0.123 / 0.123 / 0.123 / 0.123
- base gpt-4o-mini-2024-07-18: 0.243 / 0.1969 / 0.243 / 0.2123
- ft:gpt-4o: 0.986 / 0.9861 / 0.986 / 0.986
- ft:gpt-4o-mini: 0.986 / 0.9861 / 0.986 / 0.986
- ft:bert-adam: 0.975 / 0.9758 / 0.975 / 0.975
- ft:cnn_adam: 0.586 / 0.6334 / 0.586 / 0.5457

Fine-tuning metrics (Table 2; Training Loss / Validation Loss / Training Time (s) / Training Cost):
- ft:gpt-4o (API): 0.0021 / 0.0037 / 3353 / USD 54.30
- ft:gpt-4o-mini (API): 0.0081 / 0.0075 / 1779 / USD 6.52
- ft:bert-adam (Tesla V100-SXM2-16GB): 0.0294 / 0.0386 / 877 / USD 2.54
- ft:cnn-adam (Tesla V100-SXM2-16GB): 0.6253 / 0.5884 / 47.90 / USD 0.14

Key findings: Fine-tuned GPT-4o and GPT-4o-mini both achieve 98.6% accuracy (improvements of 86.3% and 74.3% over their base models, respectively), significantly outperforming CNN (58.6%); fine-tuned BERT reached 97.5%. GPT-4o-mini matched GPT-4o despite fewer parameters, at much lower cost (USD 6.52 vs USD 54.30). Zero-shot base GPT models performed poorly (12.3% for gpt-4o, 24.3% for gpt-4o-mini).

## Strengths
- Clear, reproducible experimental protocol with public code (GitHub) and consistent hyperparameters across models for fair comparison.
- Reports practical deployment factors: training time and monetary cost (USD) per model, emphasizing cost-effectiveness of smaller models (GPT-4o-mini).
- Directly quantifies the impact of fine-tuning vs zero-shot for LLMs on the same balanced test set.
- Uses a well-known balanced benchmark (WELFake) and details preprocessing steps thoroughly.

## Weaknesses
- Down-samples WELFake from ~72k to 5,000 articles and truncates to 2,560 characters, discarding long articles—limits generalizability and underuses the dataset.
- Very low zero-shot GPT-4o accuracy (12.3%) is surprising and may reflect prompt/parsing/label-encoding issues rather than true model capability; label convention (0 = fake, 1 = not fake) is nonstandard.
- CNN's low 58.6% may be attributable to insufficient labeled data / limited architecture tuning rather than a fair architectural comparison.
- Near-identical fine-tuned GPT-4o and GPT-4o-mini accuracy (both 98.6%) raises possible ceiling/overfitting concerns on an easy balanced subset.
- Language of dataset not explicitly stated.

## Limitations
Not explicitly stated as a dedicated limitations section. The paper does discuss constraints in passing: differences in token capacity between BERT/CNN (512 tokens) and GPT-4o (up to 128k tokens) required removing longer articles for fair comparison; direct comparison of training/validation losses across different architectures is challenging; zero-shot LLMs lack task-specific knowledge and prompt simplification did not improve zero-shot performance; for GPT models via API only batch size, learning rate, and epochs were controllable.

## Future Work
Not Reported (no dedicated future-work section). The Discussion outlines transformative applications of LLMs for the news industry (automated fact-checking/verification, misinformation pattern analysis, efficient allocation of journalistic resources, content moderation and community engagement) as opportunities, but does not state concrete future experiments by the authors.

## Interesting Ideas
- Model-agnostic prompt design producing structured JSON output ({'fake': integer}) for cross-LLM compatibility (GPT, Claude, LLaMA).
- Explicit cost-performance analysis (training cost in USD) framing smaller fine-tuned models (GPT-4o-mini) as sustainable, cost-effective choices.
- Standardizing input length (max 2560 chars ≈ 512 tokens) across heterogeneous architectures to enable a fair comparison.
- Observation that a smaller model (gpt-4o-mini) can equal a larger one (gpt-4o) after fine-tuning on a specialized task.

## Possible Inspiration For Our Paper
- For the Fake News Benchmark: include cost/latency (USD, seconds) alongside accuracy/F1 as first-class benchmark metrics.
- Use WELFake as a shared benchmark dataset (also used by P003), enabling cross-paper comparability.
- Adopt a model-agnostic JSON-output prompt template for evaluating multiple LLMs consistently.
- Benchmark base (zero-shot) vs fine-tuned LLMs to quantify the fine-tuning gap.

## Potential Citation Usage
- Cite for evidence that fine-tuned GPT-4o/GPT-4o-mini achieve ~98.6% accuracy on WELFake, outperforming CNN (58.6%) and matching/exceeding fine-tuned BERT (97.5%).
- Cite for the cost-effectiveness argument that smaller LLMs (gpt-4o-mini) match larger ones at ~1/8 the fine-tuning cost.
- Cite as evidence that zero-shot LLMs underperform on fake news detection without task-specific fine-tuning.

## Reviewer Notes
Well-documented, reproducible MDPI study with full DOI and public code; useful shared-dataset link to P003 (both use WELFake). Treat the extremely low zero-shot GPT-4o number (12.3%) with caution—likely sensitive to prompt/label parsing. The 5,000-sample balanced, length-truncated subset limits how strongly the near-perfect fine-tuned results generalize; good for benchmark comparability but note the reduced scale. Nonstandard label convention (0 = fake, 1 = not fake) should be normalized if reusing results.
